# 개인 작업 상태 운영 규칙

> 적용: 2026-10-02 · Agent 진입·권한은 [AGENTS](../../AGENTS.md), Git 절차는 [Git 규칙](../git-workflow.md).

## 정본과 읽는 순서

| 자료 | 소유하는 내용 |
|---|---|
| [CURRENT](./CURRENT.md) | 현재 작업 또는 진행 작업 없음, 차단, 다음 행동, 필요한 계획 링크 |
| [WORK](./WORK.md) | 여러 세션의 결과·범위·완료 조건·단계·Task·Gate·짧은 증거 |
| [DECISIONS](./DECISIONS.md) | 확인한 합의·이유·범위·대체 이력 |
| [OPEN-QUESTIONS](./OPEN-QUESTIONS.md) | 미결·해결·철회, 필요한 판단/증거와 실제 차단 범위 |
| HANDOFF (필요 시) | 실제 중단 작업의 재개 맥락 |
| Worklog (필요 시) | Git·PR로 남지 않는 중요한 비민감 실행 이력 |
| Git/GitHub | branch·diff·commit·push·PR·merge의 실제 상태 |
| [구조 계획](../개인-리팩터링-구조-계획.md) | 합의한 목표 구조·계약·이전 방향·검증 기준; 실행 Task 상태는 WORK |

Current→관련 Work/계획→필요 결정/질문/인계만 읽는다. Task·Gate 상태를 Current·Issue·제안·로그에 반복 관리하지 않는다. Current에는 merge 뒤에도 유효한 작업 경계와 관찰 조건을 남기며, 일회성 전달 작업을 닫기 위한 상태만의 PR을 만들지 않는다.

## 간단 작업과 계획 작업

- 읽기·질의·조사: 기록이나 Git 작업공간을 자동 생성하지 않는다.
- 한 번에 완료할 명확한 결과: 간단 경로. 채팅의 실행 체크리스트·Git/PR만으로 충분하면 WORK 항목 불필요.
- 여러 세션/단계·지속적 결정·질문·의존성·인계가 필요한 결과: 계획 경로. 현재 WORK에 해당 결과를 작성하고 필요한 단계만 둔다. 한 파일로 탐색이 어려워질 때만 작업별 계획 파일로 분리하며 정본은 하나다.
- 작업이 복잡해지면 남은 일만 계획으로 승격한다. 지난 세션의 일회성 단계 목록을 소급해 정식 Task로 만들지 않는다. 전체 프로젝트 roadmap·Area/WP 폴더·ID schema는 현재 필요가 없어 만들지 않는다.
- 단계는 독립 검증 가능한 결과다. Task는 해당 Gate를 위한 유동 체크리스트이며 Task마다 branch/PR을 만들지 않는다. Gate는 제출 가능한 로컬 결과인지 판정한다. branch/PR 단위는 한 결과 또는 한 단계다.

## WORK 작성·상태·완료

계획 결과마다 목표, 포함/제외 범위, 완료 조건, 지금 알려진 단계·Task·Gate와 실제 선행조건을 적는다. 모르는 미래 작업을 추측한 Task로 만들지 않는다. 미확인 필수 내용은 `미확인`, 증거가 없으면 `없음`으로 적고 해당하지 않는 선택 항목은 생략한다.

- 단계/작업: 대기·진행 중·일시정지·완료·취소.
- Task: 대기·진행 중·통과·차단·보류·취소. 수행 결과와 완료 확인 방법을 적고 실제 필요할 때만 선행조건을 추가한다.
- Gate: 대기·통과·차단·판단 불가. 기준·확인한 증거·남은 조건을 함께 적는다.
- Task/Gate는 통과, 단계는 완료일 때만 `[x]`; 다른 상태는 `[ ]`. 구현만 완료·차단·보류·취소를 체크하지 않는다. 상태와 체크를 같은 수정에서 일치시킨다.
- Task 전체 체크만으로 Gate 자동 통과 금지. 기준별 evidence·전체 diff·Secret 확인 후 Gate, 단계 완료 조건 확인 후 단계 완료로 판정한다. Gate를 통과한 결과가 달라지면 관련 Task/Gate를 재평가한다.
- 한 번에 구현·검증을 끝낸 결과는 대기→완료로 기록할 수 있지만 중간 검증을 생략하지 않는다. 진행 상태만을 위한 선행 PR이나 merge 후 상태만 바꾸는 PR을 만들지 않는다.
- 완료 결과는 당시 증거·한계를 보존한다. 변경/분할 이유를 남기고 완료 항목의 의미·실패 이력을 소급해서 바꾸거나 같은 식별 제목을 다른 결과에 재사용하지 않는다.
- 로컬 완료는 Gate 통과다. GitHub 반영/merge는 Git 정본으로 따로 확인한다. 미검증 환경은 판단 불가로 표시한다.

## 증거·실행 인계

증거마다 대상 Task/Gate, commit 또는 파일 해시·입력 식별 근거, 관찰 시점, 방법·결과·위치·한계를 기록한다. 실패·미검증도 보존한다. 다른 revision의 증거를 재사용하면 영향 재확인. 외부 로컬 자료는 다른 clone에서 접근 불가함을 적고 재검증에 필요한 비민감 요약을 남긴다.

짧은 증거는 WORK의 Gate 아래 둔다. 길어질 때만 별도 근거 문서로 분리해 정확한 링크로 연결한다. 실행 위임의 소유 경로·revision·승인 경계가 Task만으로 불명확할 때만 실행 계획 구획/문서를 추가한다. 담당자·대상·허용/제외·선행·중단·검증·반환물을 적고, 외부 변경이면 영향/복구, 비용이면 승인 상한을 추가한다. 문서 생성·완료는 승인이나 Gate 통과가 아니며 실행 직전 실제 대상과 권한을 다시 대조한다. 같은 범위의 이미 확인한 승인은 유지하되 바뀐 대상/영향으로 자동 확대하지 않는다.

## 결정·질문·연결

- 결정: 제목/날짜·활성/대체됨/폐기·합의 내용·이유·적용 범위·확인한 사용자 근거. 실제 운영 규칙은 관련 정본으로 연결한다. 미채택 후보는 제안 상태이며 결정이 아니다.
- 질문: 미결/해결/철회와 필요한 판단·근거·적용 범위. 실제 차단일 때만 차단 대상으로 표시한다. 해결 시 차단을 해제하고 이유와 결정 또는 검증 근거를 연결한다. 이력을 삭제하지 않는다.
- 연결 사실은 소유하는 기록 한쪽에만 유지한다: Work→실제 선행 Work, 새 결정→대체한 결정, 질문→차단된 작업·해결 근거, Current→활성 Work·실제 재개 인계, 로그→주 대상·만든 기록. 역관계 표를 중복 저장하지 않는다.
- 참조 대상의 존재·적용 범위·종류·중복·자기참조와 의존/대체 순환을 검사한다. 인계 재개 대상과 Current의 작업이 같아야 한다. 단순 Markdown 제목/상대 링크를 사용하며 Runtime Front Matter·UUID·전체 ID 양식은 도입하지 않는다.

## HANDOFF·Worklog·문서 배치

- HANDOFF는 실제 미완료 중단/다른 작성자 재개에만 `docs/work-status/HANDOFF.md`로 생성한다. 목표·범위·마지막 검증·미검증·남은 일·첫 행동·정확한 경로/revision/dirty 상태·보존 위치와 관련 계획을 적는다. 실제 재개 때 소비됨을 표시한다. 일반 응답 자동저장·Checkpoint만을 위한 commit은 금지한다.
- 일반 dirty HANDOFF는 WYBU의 정식 clean-commit Checkpoint와 구분한다. 저장 당시 사실/증거를 소급 덮어쓰지 않고 재개/정정 사항을 덧붙인다. 기존 dirty 문서는 사실대로 보존·인계하며 기록 때문에 commit하지 않는다.
- Git/PR로 설명되지 않는 중요한 실행·실패·검증·인계 이력이 처음 생길 때만 `docs/work-status/logs/YYYY-MM-DD.md`에 날짜·대상·요약·증거/한계·필요한 다음 행동을 append-only로 남긴다. 기존 기록의 수정은 정정 항목으로 남긴다. 상시 기록/별도 로그 index/상태 복제는 금지한다. 원팀 외부 worklog는 갱신하지 않는다.
- root는 소개 README와 AGENTS, 도구가 요구하는 manifest/config 위주로 유지한다. 운영·설계는 docs, 상태는 이 폴더, GitHub template은 .github. 기존 팀 문서를 이 규칙 때문에 옮기거나 삭제하지 않는다.
- 제안은 기존 문서를 보존하며 신규 미채택안은 필요 시 `docs/proposals/<topic>.md`에 날짜·상태·배경·대안·영향/미결·결론/반영 링크를 적는다. 초안·검토 중·채택·일부 채택·보류·기각을 구분한다. 제안 존재/채택은 실행 승인이 아니며 미결 상태는 질문 정본을 참조한다.
- 새 이름은 도구/언어 관례를 우선하고 일반 신규 파일은 짧은 kebab-case를 사용한다. 이미 채택한 CURRENT/WORK/DECISIONS/OPEN-QUESTIONS와 한국어 팀 문서는 보존한다. 기능 코드는 함께 배치하고 실제 반복/공유 필요가 생길 때만 계층·공통 패키지를 분리한다.
- 새 생성물·환경값·캐시·실행 산출 DB/로그·빌드·의존성은 commit하지 않고 ignore 여부를 확인한다. 빈 폴더·미래용 schema·소개 문서·별도 상태 index는 만들지 않는다.
